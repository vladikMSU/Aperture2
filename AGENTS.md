# Инструкции для агентов Aperture2

## Общение

- Общайся с пользователем по-русски, сохраняя привычный стиль.
- Говори о себе в женском роде: «поняла», «проверила», «сделала».
- Отличай подтверждённые решения пользователя от предложений, рабочих предположений и открытых вопросов. Не превращай обсуждение варианта в принятое решение.

## Назначение проекта

Aperture2 — личный harness для управления живыми Microsoft Excel, PowerPoint и Word через ИИ. Текущий этап ограничен Excel; первый прикладной сценарий — анализ и аудит существующей финансовой модели.

Интерфейс должен находиться в боковой панели Excel. Пользователь явно выбрал C# / VSTO, а не Office.js. Ключевое требование — работа с живым приложением и открытой пользовательской книгой, включая несохранённое состояние. Решение, которое только редактирует `.xlsx` на диске, не выполняет это требование.

Источник текущего замысла и статуса архитектуры — [README.md](README.md). Поддерживай согласованность двух документов при появлении новых решений пользователя.

У пользователя есть отдельный приватный прототип с 40+ инструментами (по его словам). Он не планирует передавать исходники сюда сейчас; возможен последующий перенос оболочки Aperture2 и подключение инструментов на другой машине. Пользователь отдельно уточнил: реализацию, запуск и проверки нужно выполнять здесь силами агента. Приватный прототип не является зависимостью или блокером текущего проекта. Скриншот нескольких контрактов не доказывает совместимость, полное покрытие или проверенную надёжность.

## Агентный runtime

- Используй [Pi Coding Agent](https://github.com/earendil-works/pi) как агентную основу.
- Агентный цикл ReAct, взаимодействие с моделью и провайдерами, соответствующую сетевую работу и цикл вызовов инструментов оставляй Pi. Не создавай в Aperture2 второй самостоятельный агентный цикл.
- Задачи Aperture2 — интерфейс, интеграция с сессиями Pi и инструменты управления Office.
- Основа первого прототипа — [RPC-режим Pi](https://pi.dev/docs/latest/rpc), уточнённый пользователем. VSTO запускает Pi по требованию через CLI и асинхронно обменивается командами и событиями через stdin/stdout.
- Рабочая схема MVP — один процесс Pi на активный чат, история средствами Pi, без отдельного сервера-координатора. Постоянный фоновый хост остаётся возможным следующим этапом.
- В текущей схеме Pi подключает внешний Excel MCP как дочерний stdio-сервер. Различай RPC-канал чата и MCP-канал инструментов. MCP-backend выполняет операции через COM после подтверждения целевого экземпляра Excel и книги.
- Не описывай stdio RPC как готовый HTTP/WebSocket-сервер. Отдельно определяй запуск процесса, транспорт и управление сессиями.
- Перед реализацией интеграции проверь API выбранной версии Pi по upstream-документации и зафиксируй зависимость. Не переноси имена пакетов и API из старых примеров без проверки.

## Рабочая архитектура

- Пользователь закрепил VSTO и делегировал остальные архитектурные решения; для интерфейса указал на WebView2 из своего прототипа. Здесь чат переведён на WebView2 (HTML/CSS/JavaScript) в VSTO task pane. Реализованы Pi RPC и собственный MCP-адаптер с импортом выбранных операций ThepExcelMCP. Upstream подключён закреплённым submodule без модификаций; точная привязка и очередь COM реализованы в `src/aperture_mcp`. Реальные Excel, WebView2 и Pi/MCP проверяются через live smoke; отдельный `--model-smoke` проверяет API и вызовы инструментов через `openrouter/free` после авторизации.
- VSTO, боковая панель и клиент Pi находятся внутри процесса Excel. Книги принадлежат этому же экземпляру приложения, но не надстройке. В текущей схеме исполнитель находится во внешнем MCP-backend. Сохраняй правильные границы приложения и книг на схемах.
- При расширении сравнивай приватный прототип пользователя, полный форк Excel MCP, выделение библиотеки, перенос отдельных операций и новую реализацию. Текущая зависимость — закреплённый ThepExcelMCP; история выбора находится в `docs/tooling-choice.md`.
- Приоритет — работоспособная оболочка вместе с доступными здесь инструментами, без ожидания приватного кода. Отделяй UI и Pi-сессии от каталога/исполнения через MCP, чтобы позднее заменить backend или подключить приватные инструменты через адаптер. Не строй заранее универсальную систему плагинов.
- VSTO передаёт контекст своего приложения, внешний MCP-backend подтверждает привязку и выполняет команды. Для любого backend обеспечь точную цель и согласованный порядок записей; не создавай два конкурирующих контроллера одной книги.
- VSTO и RPC-клиент работают на .NET Framework 4.8. WinForms — контейнер WebView2; основной чат находится в `src/Aperture.Excel/Web`, диалог настроек пока нативный. Не переноси чат обратно на RichTextBox. Современный .NET допустим в будущих внешних адаптерах.
- Решение пользователя: панель открывается только по запросу, как Claude и ChatGPT for Excel, — кнопкой-переключателем в своей группе Aperture2 на вкладке «Главная» или `Start` COM-входа. Не создавай и не показывай панели на запуске Excel и при активации окон. Одна панель на окно, панели закрытых окон убираются.
- Решение пользователя: в шапке только «Новый чат» и настройки, прижатые вправо, высотой по кнопкам; имени книги, перепривязки, значка и названия продукта нет — заголовок «Aperture2» даёт область задач Excel. Под полем ввода нет строки статуса, поле и «Отправить»/«Стоп» стоят в одной строке. Ход запроса показывает его карточка, а ошибки и важные факты (неподтверждённая остановка, неизвестный итог, отказ, заметки панели) идут в ленту: в карточку идущего запроса, иначе отдельной строкой, без повторов подряд. Транзиентные статусы («Думаю…», «Подключаю агента…») не возвращай. Stderr Pi в ленту не выводи построчно; ошибки, после которых запрос не может продолжиться, показывай.
- Дополнительный named pipe не обязателен для внешнего COM-backend. Если позже инструментам понадобится исполнение внутри VSTO, можно добавить локальный канал к MCP-адаптеру; определить идентификацию соединения и ACL. Не навязывай этот мост готовому MCP без необходимости.
- Сравнивай переиспользуемые решения по доступу к несохранённой книге, операциям аудита, надёжности, лицензии и стоимости поддержки. Не переноси чужие политики сохранения, закрытия и завершения Excel без проверки.
- При оценке трудозатрат отдельно учитывай изучение кода, адаптацию runtime/COM lifetime, интеграцию, реальные проверки и дальнейшую поддержку форка. Сравнивай одинаковое покрытие; не считай весь каталог чужого MCP обязательным для MVP и не приравнивай перенос кода к бесплатной интеграции.
- Полный форк и выборочное заимствование — разные варианты. При переносе кода сохраняй источник, ревизию и необходимые лицензионные уведомления. Не назначай точные сроки интеграции приватного прототипа по скриншоту.
- Не принимай поддержку MCP или успешный `tools/list` за доказательство управления живым Excel.
- Тестовый исполнитель допустим для разработки UI, но не заменяет локальную приёмку с настоящими инструментами и живым Excel. Сборка и запуск здесь не должны зависеть от приватного прототипа.
- Учитывай будущие Word и PowerPoint в границах компонентов; не реализуй их в рамках текущего этапа без расширения задачи пользователем.

## Поведение агента в Excel

- Обычные изменения выполняются по запросу пользователя в чате без обязательного предварительного согласования каждого действия.
- Удаление, закрытие и другие рискованные действия требуют подтверждения. Не запрашивай повторно подтверждение конкретного действия, которое пользователь уже явно подтвердил.
- Запрос на аудит не является разрешением на незапрошенные исправления исходных расчётов. Разделяй диагностику и изменение модели.
- В замечаниях указывай проверяемые ссылки на листы, ячейки или диапазоны и различай наблюдаемые ошибки, предположения и рекомендации.
- Формат отчёта аудита и механизм восстановления изменений остаются открытыми решениями; не выдавай предложение за готовую функцию.

## Инженерные ориентиры для живого Excel

- Адресуй операции через явные `excelInstanceId` и `workbookId`, действующие в текущем запуске. Не полагайся только на имя файла или активное окно. После закрытия книги или перезапуска приложения явно восстанавливай привязку.
- Первое сохранение и Save As меняют имя и путь той же книги. По решению пользователя чат следует за ней сам. Текущая реализация: новое имя берётся только из захваченного объекта книги в том же окне, ID остаются, следующий запрос перезапускает Pi/MCP с новой целью и тем же файлом истории (`--session`). Если прежний Pi уже завершился, начинается новая сессия с системной строкой в ленте. Закрытую, заменённую или недоступную книгу молча не подхватывай: это ошибка, а «Новый чат» привязывает книгу своего окна заново.
- Сетевое ожидание, RPC и IPC выполняй асинхронно. Внутри VSTO обращения к объектной модели диспетчеризуй в основной UI-поток Excel; во внешнем COM-backend соблюдай его модель STA и маршалинга. Не блокируй UI ожиданием ответа Pi.
- Не полагайся на `SynchronizationContext` Excel: после `await` явно диспетчеризуй работу с контролами, WebView2 и COM. Ожидание `OnUiAsync` само по себе не переводит последующее продолжение на UI-поток. Регрессии проверяй с отсутствующим контекстом и включённым контролем межпоточного доступа. Модальные диалоги открывай вне WebView2 COM callback через очередь UI.
- Показывай Markdown во время стриминга и фактический ход работы Pi: предоставленные reasoning-блоки, начало/прогресс/результат инструмента. Сопоставляй инструменты по `toolCallId`; отсутствие reasoning или промежуточного результата не заменяй придуманным содержимым. `message_end` завершает сообщение, `agent_settled` — весь запрос; между ними возможны новые инструменты, повторы и ответы.
- Пользователь просит видеть все tool calls. По умолчанию показывай каждый вызов отдельной строкой, в том числе повторные вызовы одного имени и формирование аргументов до исполнения (`toolcall_*`). Свернуты только подробности, а не список вызовов. События формирования и исполнения одного ID должны обновлять одну карточку, а не создавать дубли.
- Лента запроса хронологическая: текст, рассуждения и вызовы стоят в порядке событий (`contentIndex` внутри сообщения), промежуточный текст не уносится вниз, а шаги — в отдельную карточку сверху. Контроллер передаёт в представление сырые события Pi, включая `text_*`; представление само собирает ленту. Сворачивание запроса скрывает ход работы, но не итоговый ответ.
- Остановка или сбой Pi и MCP-адаптера не должны закрывать Excel или терять несохранённые изменения. Управляй только собственными дочерними процессами и соединениями.
- Внешний COM-клиент не держит ссылок на объекты Excel между операциями. Job Object убивает MCP при закрытии чата или Excel; ссылки убитого клиента остаются зарегистрированными, и закрытый пользователем Excel висит скрытым процессом. Освобождай ссылки, включая кадры traceback исключений, до возврата результата.
- Текущие инструменты не меняют глобальные `Calculation`, `ScreenUpdating`, `EnableEvents` и `DisplayAlerts`. Сохраняй это свойство: жёсткое завершение MCP может не выполнить `finally`, поэтому одного восстановления в `finally` недостаточно. Если будущая операция требует переключений, отдельно реши восстановление после аварийного завершения.
- Для массовой обработки предпочитай операции с диапазонами. При использовании COM учитывай требования потоков, занятость приложения и локаль.
- Не выполняй слепой повтор изменяющей операции после тайм-аута: сначала выясни, была ли она применена.
- Отмена ожидания не гарантирует остановку уже выполняющегося COM-вызова. Не обещай откат или обычный Excel Undo без отдельной реализации и проверки.
- Не подменяй текущую открытую книгу скрытой копией файла и не сохраняй или закрывай её как побочный эффект чтения.
- Проверяй интеграцию на тестовых книгах: чтение, запись, пересчёт, повторное чтение и видимость результата в пользовательском Excel. Сохранение и закрытие проверяй отдельными явными действиями.
- Проверяй привязку книги, отмену и восстановление состояния при ошибке. Сообщай, что действительно проверено, а что остаётся неподтверждённым.
- Не утверждай, что интерфейс или оформление визуально проверены, если проверено только содержимое ячеек.

## Работа с репозиторием

- Пользователь хочет обычный проект Visual Studio: сборка `Aperture2.sln` в VS (или VS MSBuild из командной строки) готовит submodules, Pi и `.venv` через `build/Aperture.Dependencies.targets`, подписывает и регистрирует Debug-надстройку через `build/Aperture.Signing.targets`. Не возвращай отдельные скрипты установки/сборки/регистрации. Для VSTO нужен MSBuild из Visual Studio с Office targets, не `dotnet build`.
- Не очищай метку `Aperture2-Development` в `ManifestCertificateThumbprint` csproj: при пустом значении Visual Studio генерирует `*_TemporaryKey.pfx` и переписывает проект. Сборка в worktree перерегистрирует надстройку на путь этого worktree; после работы пересобери основной checkout или верни регистрацию. Excel, запущенный через COM (`DispatchEx`), здесь загружал сборку основной папки независимо от регистрации, а обычный `excel /x` — зарегистрированную: сборку worktree проверяй через `excel /x`. Новый обычный Excel параллельных сессий тоже берёт зарегистрированную сборку, поэтому не держи регистрацию на worktree дольше проверки.
- `scripts/test.ps1` запускает backend, runtime и тест панели после Debug-сборки решения; `-Live` запускает отдельный Excel с собственными тестовыми книгами. Не используй пользовательские книги для технических smoke. Не закрывай Excel по имени процесса; освобождай только созданные тестом экземпляры и книги.
- Новый профиль панели по умолчанию использует `openrouter` / `openrouter/free`. Провайдеры и авторизация принадлежат Pi; не пиши второй API-клиент LLM. Сохранённый выбор пользователя не перезаписывай. Настройка — `node external\pi\packages\coding-agent\dist\bundle\cli.js`, затем `/login openrouter`; API-ключи не проси в чате.
- Бесплатный router может менять модель. Для повторяемых сравнений закрепляй конкретную доступную модель с tool calling. Успешный `get_state` или выбор модели не доказывает успешный запрос к API.
- Пользовательские OpenAI-совместимые провайдеры (RouterAI, внутренний API) описываются в `~/.pi/agent/models.json`, ключ — только ссылкой `$ИМЯ` на переменную окружения. Стоимость Pi — оценка по ставкам `cost`; агрегатор может списать больше (RouterAI через BytePlus — в 2,8 раза). Фактическую стоимость даёт `usage.cost` провайдера; Pi его отбрасывает, в историю попадает только оценка. Excel, запущенный через COM, получает окружение входа в систему без переменных, заданных позже; ключи, на которые ссылается `models.json`, `SessionConfiguration` берёт из пользовательского окружения и передаёт только процессу Pi. Значения ключей не печатай и не записывай.
- `AgentAutomation` (`Application.COMAddIns("Aperture.Excel").Object`: `GetInfo`, `Start`, `GetState`, `Cancel`, `StartWithThinking`) — пульт обычного чата для скриптов, в том числе внешнего бенчмарка. `Start` открывает панель книги, начинает новый чат с моделью скрипта и отправляет промпт как пользователь; `StartWithThinking` делает то же с уровнем рассуждения Pi (`--thinking`) только для этого чата, `GetState.thinking` — действующий уровень из `get_state` Pi. Новые методы dual-интерфейса добавляй только в конец, сигнатуры прежних не меняй. `Cancel` — кнопка «Стоп». Отдельного режима, своих форматов записей и кода специально для бенчмарка нет: тот же контроллер, `SessionConfiguration`, системный промпт, инструменты и история Pi. aperture2 — оцениваемый агент: не подгоняй под бенчмарк промпт, инструменты или поведение и не читай его эталоны, отчёты и прогоны. Smoke — `tools/AutomationSmoke/smoke.py`, только на собственных синтетических книгах; запрос платный.
- Панели всех Excel делят профиль WebView2 `%LOCALAPPDATA%\Aperture2\webview2`. Excel с другими аргументами браузера (например, `--remote-debugging-port` для CDP) поднимает браузер этого профиля со своими опциями, и панели остальных Excel получают 0x8007139F, пока он жив. Не меняй профиль без решения пользователя.
- Добавляй команды в README по мере появления рабочей реализации. Не выдавай планируемую функциональность за существующую.
- Не сохраняй ключи провайдеров, токены, личные книги и историю с содержимым финансовых моделей в Git.
- Для изменений только в документации проверяй содержимое и согласованность; запуск Excel и тесты runtime не требуются.
