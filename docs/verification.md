# Техническая проверка первой версии

Дата: 14 октября 2026. Среда: Windows, настольный Excel Microsoft 365 x64, VS 2022 Community / .NET Framework 4.8, Node 24.18, Python 3.12. Это проверка интеграции; пользовательская приёмка и запросы к LLM не выполнялись.

## Сборка и тесты

- Закреплённый Pi собран из исходников; установленные Python-зависимости проходят `pip check`.
- `scripts/build.ps1`: Runtime, Excel VSTO с подписанными manifests, PiSmoke — успешно.
- `scripts/test.ps1`: 8 backend-тестов; 5 проверок протокола/жизненного цикла Pi; 16 assertions панели с тестовыми зависимостями — успешно.
- `git diff --check` — без ошибок пробелов.

Тесты панели компилируют настоящий `ChatPaneControl.cs`. Проверяют Stop и Dispose во время незавершённого старта, невозможность параллельного Send при Rebind/«Новый чат». Они не подменяют live smoke.

## Живой Excel

Последний полный прогон: `.local/smoke/a74244acbf7a40d7b5e8fb8f2fc8fee0/report.json` (локально, не в Git).

- Excel запущен обычным способом в отдельном процессе; VSTO загрузилась и создала настоящую task pane.
- Две собственные несохранённые книги. `paneId` и `boundWorkbookId` стабильны при переключении активного окна и трёх интервалах таймера очистки; все привязки проходят реальную проверку VSTO.
- MCP записал 20 и 22, записал `=SUM(A1:A2)`, пересчитал лист и прочитал 42. Активной в это время была вторая книга; её контрольные значения и формулы не изменились.
- Неверный `workbookId` отклонён. Обзор корректно обработал отдельный лист диаграммы. Книга осталась несохранённой; глобальные настройки Excel не изменились.
- Реальный Pi запустился через RPC и подключил все 10 MCP-инструментов. Дочерние Pi/MCP завершились. API модели не вызывался.
- После закрытия контрольной книги её панель удалена, оставшаяся панель и привязка сохранились.

## Границы подтверждённого результата

В этом прогоне после `Quit` и освобождения внешних COM-ссылок пустой тестовый Excel оставался фоновым процессом. Harness завершил именно созданный им процесс по сохранённому handle после подтверждения нуля книг и отсутствия видимых окон. Отчёт явно содержит `normalExit=false`, `forcedTermination=true`; штатный выход процесса этим прогоном не доказан. Это поведение тестовой очистки, оно не добавлено в продукт: Aperture2 не завершает процесс Excel.

Два последующих минимальных запуска обычного Excel завершились штатно (`normalExit=true`, `forcedTermination=false`): с загруженной VSTO и с отключённой через `Connect=false` надстройкой. Оба выполнялись без обращения к диагностическому `COMAddIns.Object` и без MCP-нагрузки. Поэтому минимальный путь загрузки/выгрузки надстройки проверен, а причина удержания процесса в полном COM smoke отдельно не установлена. `Connect=false` также изменил сохранённый Office `LoadBehavior`; после диагностики developer-регистрация восстановлена. Локальный отчёт: `.local/smoke/lifecycle-isolation-c647f5ccc10045b3a117ac74f63b5988/report.json`.

Не проверены реальный ответ OpenRouter и качество tool calling/аудита, визуальное удобство панели, большие финансовые модели, все сочетания сторонних надстроек и несколько одновременно работающих процессов Excel. Авторизация модели выполняется отдельно через Pi. Для пользовательских книг нет автоматического сохранения, удаления, закрытия или обещанного отката.
