# Проверка веб-интерфейса чата

`chat-view.cjs` открывает настоящие `Web/chat.html`, `chat.css` и `chat.js` в headless-браузере. WebView2 bridge заменён тестовым объектом; текст аудита и ссылки на ячейки вымышлены. Тест не запускает Excel, Pi или модель и не заменяет live smoke надстройки.

Требуются Node.js, доступный через `require('playwright')` Playwright и установленный Microsoft Edge. Playwright — внешняя тестовая зависимость, в продукт он не добавляется. Если пакет уже установлен отдельно, задайте `NODE_PATH` на каталог, содержащий пакет `playwright`; `scripts\test.ps1` запускает этот тест, когда пакет находится, и сообщает о пропуске иначе.

Запуск из корня репозитория:

```powershell
node tests/web/chat-view.cjs
```

По умолчанию используется канал `msedge`. Для другого установленного Chromium-браузера задайте `APERTURE_BROWSER_EXECUTABLE` с полным путём к исполняемому файлу.

Тест выполняет **136 проверок**:

- Шапка и нижний блок: в шапке нет имени книги и перепривязки, только «Новый чат» и настройки; под полем ввода нет строки статуса, в строке поля только «Отправить»/«Стоп». Пустое однострочное поле не показывает полосу прокрутки со стрелками, в том числе заблокированное скриптом при 320 px; прокрутка появляется только у текста выше предела роста поля.
- Composer: Enter отправляет, Shift+Enter переносит строку; отправленный текст защищён до `clear_prompt`, затем можно набирать следующий вопрос, но не отправлять его до окончания работы; Stop, повторный Stop, настройки и новый чат; запрос, отправленный скриптом через COM-вход, блокирует поле ввода с обычной подсказкой, сохраняя черновик и кнопку Stop.
- Уведомления вместо строки статуса: заметка и ошибка вне запроса — отдельные строки, повтор той же ошибки подряд не добавляет вторую строку; предупреждение и ошибка во время запроса — в его карточке, один раз; ошибка завершает карточку. «Стоп» во время вызова инструмента или до первого события Pi всё равно заканчивает карточку строкой «Ответ остановлен», без повтора.
- **Хронология**: рассуждение, текст, вызов, текст, вызов и рассуждение, итоговый текст идут в DOM в порядке событий модели; итоговый ответ помечается после `agent_settled`, сворачивание запроса скрывает шаги и промежуточный текст, но не ответ.
- Markdown **до `message_end`**: заголовок, `---` как разделитель (а не три дефиса), жирный и курсив, таблица с выравниванием, вложенный список, цитата, незакрытый блок кода; authoritative `message_end` заменяет частичный текст без дублей.
- Безопасность: HTML, ссылки и `<script>` из ответа и аргументов остаются текстом, ничего не исполняется и не загружается.
- Вызовы: независимые `toolCallId`, завершение в другом порядке, ошибка отдельного вызова, Excel-подобный контекст (`DCF!A1:D8`, текст поиска), ленивые аргументы/результаты и предел показа 40 000 символов.
- Рассуждения: delta → end → fallback из `message_end` без дублей; пустое, redacted или отсутствующее в итоговом сообщении рассуждение удаляется; подпись thinking не показывается. Ошибка провайдера стоит в ленте.
- Все вызовы видны с формирования: `toolcall_start/delta/end`, неизвестные и повторяющиеся имена, fallback-вызов только из `message_end`, повторные callbacks без дублей, заголовок запроса показывает формирующийся вызов.
- Пробельный текст между шагами не создаёт пустой блок и не разрывает группу шагов; «Стоп» показывается нейтральной строкой «Ответ остановлен», а не ошибкой «Request was aborted»; футер сводит модели free router («openrouter/free → 2 модели»), полный список — в подсказке.
- Завершение: `agent_end` не закрывает запуск до `agent_settled`; отмена не выдаёт незавершённую COM-операцию за остановленную («нет результата»), неисполненные вызовы — «не исполнен»; `aperture_run_end` с ошибкой перекрывает обычное завершение.
- Прокрутка не утаскивает читателя выше хвоста; шапка — одна строка 40–50 px, без горизонтального переполнения при 320/410/760 px; светлая тема переключает палитру; нет ошибок JavaScript и внешних запросов.

Fixtures следуют закреплённым контрактам Pi: `packages/agent/src/types.ts`, `packages/ai/src/types.ts` и JSON/RPC-событиям без накопительного `partial`.

Скриншоты создаются в игнорируемом `work/`: `chat-webview-welcome.png`, `-conversation.png`, `-streaming.png`, `-collapsed.png`, `-narrow.png` (320 px), `-light.png`, `-all-tools.png` и нижний блок в низкой панели: `-composer-idle.png` (покой), `-composer-busy.png` (идёт запрос), `-composer-error.png` (после ошибки). Текст на них синтетический.

Успех возвращает JSON с `passed: true` и `checks: 136`. При ошибке процесс возвращает ненулевой код и закрывает запущенный им браузер.
