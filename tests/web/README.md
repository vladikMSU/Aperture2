# Проверка веб-интерфейса чата

`chat-view.cjs` открывает настоящие `Web/chat.html`, `chat.css` и `chat.js` в headless-браузере. WebView2 bridge заменён тестовым объектом; текст аудита и ссылки на ячейки вымышлены. Тест не запускает Excel, Pi или модель и не заменяет live smoke надстройки.

Требуются Node.js, доступный через `require('playwright')` Playwright и установленный Microsoft Edge. Playwright — внешняя тестовая зависимость, в продукт он не добавляется. Если пакет уже установлен отдельно, задайте `NODE_PATH` на каталог, содержащий пакет `playwright`.

Запуск из корня репозитория:

```powershell
node tests/web/chat-view.cjs
```

По умолчанию используется канал `msedge`. Для другого установленного Chromium-браузера задайте `APERTURE_BROWSER_EXECUTABLE` с полным путём к исполняемому файлу. Путь к репозиторию определяется по расположению скрипта, поэтому запуск из другого рабочего каталога тоже допустим.

Тест выполняет **78 проверок**:

- Send/Stop/Settings, Ctrl+Enter, блокировка действий и ввода во время работы.
- Markdown **до `assistant_end`**: заголовок, выделение, таблица, незакрытый блок кода; немедленный финальный flush и замена неполного текста авторитетным ответом.
- Два сообщения модели и один инструмент: reasoning приходит частями, затем в `thinking_end` и `message_end`, без повторных блоков. Это синтетическая последовательность; содержимое пользовательских книг и истории не используется.
- Несколько параллельных вызовов: независимые `toolCallId`, прогресс, завершение в другом порядке, ошибка отдельного инструмента, корректные счётчики шагов.
- Все строки вызовов видимы по умолчанию; свёрнуты только аргументы, результаты и reasoning. `toolcall_start` показывает формирующийся вызов до исполнения, `toolcall_delta` накапливает JSON аргументов, `toolcall_end` заменяет его окончательными аргументами. Execution callbacks обновляют ту же строку по ID.
- Разные ID с одинаковым именем, неизвестные инструменты, fallback из `message_end` без стриминга и повторные callbacks без дублирования строк.
- Ленивая отрисовка аргументов/результатов при раскрытии и явное ограничение показа большого результата до 40 000 символов.
- Отмена и ошибка провайдера; `agent_end` не завершает запуск до `agent_settled`; удаление пустого, отсутствующего или redacted reasoning из окончательного сообщения.
- Отмена до исполнения даёт статус «Не исполнен». Уже начатая операция без результата помечается «Нет результата»: остановка ожидания не доказывает остановку COM-операции в Excel.
- Безопасный вывод HTML в ответах и аргументах, отсутствие непрозрачных thinking signatures, ошибок JavaScript и внешних запросов.
- Сохранение положения прокрутки при чтении выше текущего ответа; шапка 70–90 px и отсутствие горизонтального переполнения при ширине 320/410/760 px.

Fixtures следуют закреплённым контрактам Pi: `packages/agent/src/types.ts`, `packages/ai/src/types.ts` и JSON/RPC-событиям. В частности, проверяется wire-последовательность `thinking_delta` **без `partial`**; `thinking_end.content` и окончательный `message_end.message.content` заменяют накопленный текст.

Скриншоты создаются в игнорируемом `work/`:

- `chat-webview-welcome.png` — начало чата, 410 × 850.
- `chat-webview-conversation.png` — синтетическая переписка с таблицей, 410 × 850.
- `chat-webview-narrow.png` — узкая панель, 320 × 650.
- `chat-webview-streaming.png` — синтетический ответ **до окончания стриминга**, уже оформленная таблица и раскрытая активность с двумя шагами модели, тремя инструментами и полученным reasoning; 410 × 1040.
- `chat-webview-all-tools.png` — три видимых вызова неизвестных инструментов, включая повтор одного имени с другим ID и ещё формирующийся вызов; 410 × 850.

Успех возвращает JSON с `passed: true` и `checks: 78`. При ошибке процесс возвращает ненулевой код и закрывает запущенный им браузер.
